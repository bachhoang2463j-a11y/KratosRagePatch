# 实现战斗中每次有效命中固定加怒（0.3.0）

## 本次行为

- 使用原生 `TESHitEvent`，不依赖 PO3，不恢复实际血差钩子。
- 玩家战斗中每个通过筛选的命中固定 **+2 怒气**；同一目标快速多段、多目标命中分别累计，默认 100 点上限需要 50 次有效命中。
- **取消按战斗时间增长**。保留现有 `TickCombat` 心跳，仅用于战斗状态、脱战/死亡清零、变身状态与激活事务对账。
- 不套用旧版每秒 10 点预算或 0.1 秒合并窗口，以免吞掉真实连击。总怒气仍封顶。一次接受的原生事件计一次；事件没有唯一命中编号，不在缺少实测依据时猜测合并。
- 有效目标按保守默认规则：玩家本人发起、目标为 Actor、非自己、非队友/玩家或队友直接指挥的角色、对玩家敌对、事件到达时目标未死亡，且命中未标记为格挡。非战斗、玩家死亡、暂停、菜单、加载或尚未完成读档对账时不授予。
- 不要求验证目标实际掉血，所以免疫但仍产生未格挡命中事件的情况不额外做血差判断。无事件的特殊攻击不能凭动画猜测命中。
- 不新增装备积攒门槛，维持当前装备仅限制释放；pending/raging 本身不禁止积攒。击杀不额外奖励，也不做技能差异奖励。

## 明确的事件边界

`TESHitEvent` 没有首击、致命击或施放实例标记。目标在事件到达时活着、入队后才死亡，不因排队延迟拒绝；事件到达时已死亡则拒绝。开战首击、死亡状态翻转和原 MOD 特殊攻击覆盖需用户游戏测试，不能把离线测试说成已验证这些引擎行为。

## 修改与复用

1. **规则层**：新增小型 `TryAwardCombatHit(inCombat, suspended)` 定额接口，复用账本、上限、满怒边沿和存档逻辑。旧命中/伤害/计时规则保留为历史测试对象，不进入生产积攒链，不新增模式开关。
2. **桥接层**：注册一次 `TESHitEvent` sink；捕获事件数值、瞬时状态与可重解析的目标句柄，再通过现有 generation 守卫投递主线程任务。执行时检查加载/暂停及玩家状态，更新账本后同步 ready marker 和 HUD 事件。
3. **诊断**：区分事件接收、拒绝原因、实际授予与满额，并提供限流日志。限流只限制日志，不限制计分。保留来源/投射物 ID，方便后续验证特殊攻击，不提前实现技能奖励表。
4. **兼容**：17 个 Papyrus native 签名不变，旧 `Submit*` 和 `SubmitPlayerDamage` 仍无操作。ESP、OAR、PI、配置及 UI 不改；复用 0.2.0 的 PEX/SWF，说明 UI 日志仍标组件版本 0.2.0。
