# KratosRagePatch 接手续作计划

## 范围与已确认目标

沿用现有 Skyrim SE 1.6.640 / SKSE 2.2.3 的独立补丁方案，不更换技术栈，不重做原 MOD。

- 怒气默认上限 100；普通命中 2、重击 4、特殊命中 3、受击 1、击杀 5；所有来源共享滚动每秒 8 点上限。
- 同目标、同来源 0.1 秒内去重；仅装备条件允许时积攒；变身及待确认期间不积攒。
- 仅满怒允许原变身；确认原变身效果生效后才清空怒气，失败不扣、不通过预扣退款实现。
- 保留原操作方式、装备条件及动画资源。OAR 使用三个独立 Ready 组追加满怒条件，不复制 HKX。
- 自有怒气条、怒气不足闪红、满怒短暂红金色身体泛光；JSON 配置，不新增 MCM 或热键。
- 原 MOD 只读。仅在项目目录构建；不安装到 MO2、不改 profile、不启动游戏或桌面 UI。

## 执行与验收

1. **补齐原生构建依赖**：工程内固定版本 fmt、spdlog 和 CommonLibSSE-NG，完成 DLL Release 构建，不改系统环境。
2. **闭合运行链路**：对齐原生计分白名单与审计数据；核验变身事务、原载荷的单次施放、事件来源、存档恢复和原操作门槛；核验 VMAD 对象绑定与脚本/UI 初始化。
3. **重跑离线验证**：怒气账本与事务测试、ESP/VMAD 反解析、OAR/PI 原条件/原行保留、Papyrus 官方与交叉编译、AS2 编译及结构校验；不以编译通过冒充游戏内验证。
4. **打包交付**：从通过检查的 staging 生成独立 MO2 ZIP，包含 DLL、ESP/SEQ、PEX、SWF、配置和必要覆盖文件；提供构建/安装说明、哈希清单、验证记录与游戏内验收项目。
5. **保护原文件**：结束时复算原 MOD 哈希，与本次接手基线一致。

## 完成标准

- DLL、脚本、插件、界面和配置同时存在，所需原生/Papyrus接口一致；离线测试无失败。
- 安装包不包含第三方 DLL、HKX、原 MOD 资源、编译工具、缓存或虚构的验证结论。
- 清晰标注仅支持 1.6.640，以及未做游戏内实测的边界。游戏内动作、泛光、HUD 外观、存档加载由用户安装后验收。
