# KratosRagePatch 接手续作计划

## 范围与已确认目标

沿用现有 Skyrim SE 1.6.640 / SKSE 2.2.3 的独立补丁方案，不更换技术栈，不重做原 MOD。0.3.0 的积攒口径为：

- 仅使用原版 `TESHitEvent`（不依赖 PO3）。战斗中每个通过筛选的命中固定 **+2**，怒气默认上限 100，因此默认需要 50 次有效命中。
- 不做 0.1 秒同源去重，也没有每秒预算；同一目标快速多段、多目标命中分别累计，总怒气封顶。
- 筛选：玩家本人发起、目标为活着的 `Actor`、非自己/队友/玩家或队友直接指挥者、对玩家敌对、未标记格挡。到达时已死亡拒绝；到达时活着、入队后才死亡不因排队拒绝，但仍需句柄和敌对/友军检查。
- 不验证目标实际掉血；免疫但仍产生未格挡命中事件照常计分。无事件的原 MOD 特殊攻击不凭动画猜测命中。
- 无装备积攒门槛，未完成配置时也按默认积攒；变身及待确认期间不阻止积攒。
- 取消按战斗时间增长。保留 `TickCombat` 心跳，仅用于战斗状态、脱战/死亡清零、变身状态与激活事务对账。
- 旧 `Submit*` 与 C++ `SubmitPlayerDamage` 保持无操作；受击、击杀事件不计分，击杀不额外奖励。
- 其余不变：仅满怒允许原变身，确认原效果生效后才清空怒气（失败不扣、不预扣退款）；OAR 三个独立 Ready 组；自有 HUD；JSON 配置、不新增 MCM/热键；原 MOD 只读，不安装到 MO2、不改 profile、不启动游戏或桌面 UI。

17 个 Papyrus native 签名与存档 schema 不变；ESP/SEQ、PEX、SWF、OAR/PI 及 `config.json` 逐字节复用 0.2.0，只有 DLL 升级为 0.3.0。发行目标是 `dist/KratosRagePatch-0.3.0-skyrim-1.6.640.zip`，旧包冻结不改。

## 2026-09-29 0.3.0 命中定额方向（当前）

用户已批准把积攒输入从“战斗计时每秒 +2”改为“原生命中事件每次通过筛选 +2”，回复 0.2.0 时间链路“基本可用”的体验反馈保留为 0.2.0 的历史证据，不改写为 0.3.0 的验证结论。

- 规则层新增小型 `TryAwardCombatHit(inCombat, suspended)` 定额接口，复用账本、上限、满怒边沿与存档；旧命中/伤害/计时规则保留为历史测试对象，不进入生产积攒链，不新增模式开关。
- 桥接层注册一次 `TESHitEvent` sink，在事件到达与主线程任务执行两个时点都检查战斗/暂停/菜单/加载/对账/玩家状态，并解析目标句柄与敌我关系；诊断按接收、拒绝原因、实际授予与满额区分，每类每秒限流一条，限流只作用于日志、不限制计分。
- 运行资产逐字节复用 0.2.0（仅 DLL 变为 0.3.0），UI 组件自报版本仍是 0.2.0；17 native 签名与存档 schema 不变。
- 未配置时也可按默认积攒；pending/raging 不禁积攒；无装备积攒门槛。
- 离线测试不能证明引擎首击、致命击和特殊攻击语义，需用户用 0.3.0 包在游戏内验收：首击计分、致命击（到达时活着、入队后死亡）计分、原 MOD 特殊攻击是否有未格挡命中事件覆盖。本次不验证实际掉血，免疫但有未格挡事件可计分。
- 不安装 MO2、不改 profile/INI、不启动游戏。实际执行证据记录在 `docs/verification.md`。
